# Discovery Response Workflow: AI-Native with Verification Gates

Author: Jonathan W. Doolan. Demonstration workflow on wholly invented
case materials. The doctrine in one line: the model drafts, the record
governs, and a written gate stands between every draft and the
signature.

## The five stages

STAGE 1, INTAKE (protocol 01). Every request is parsed into a
structured checklist before any document is touched. Each request gets
a scope note and an objection posture set by the attorney. The model
executes posture; it never chooses posture.

STAGE 2, TRIAGE (protocol 02). The document set is run against the
request checklist. Every responsiveness call carries a citation to the
exact document and passage. An uncited call is a failed call.

STAGE 3, PRIVILEGE GATE (protocol 03). A separate pass under a written
privilege protocol, run before drafting, not after. Clear privilege is
flagged and logged. Anything borderline is routed to human review by
rule. The gate is designed to over-refer, never to over-clear.

STAGE 4, DRAFTING (protocol 04). Response shells are generated per
request. Objections are preserved from the intake posture. Answers are
scoped to the question asked; volunteering is a defect, not a courtesy.

STAGE 5, VERIFICATION (protocol 05). The stage most workflows skip. A
checklist pass re-grades every draft against the record: every factual
assertion re-cited, every date cross-checked across documents, every
answer measured against its question's actual scope. Discrepancies
surface here or they surface in a deposition.

## Why the gates exist

A frontier model is impressive on the median document and wrong in the
tails. Legal work lives in the tails. The gates are not distrust of the
tool; they are the same discipline a supervising attorney owes any
first-year's draft, written down and made executable.
